# Feature Documentation Standard

Padrao reutilizavel para documentar funcionalidades.

## Estrutura Recomendada

```text
docs/<module>/
  overview.md
  api.md
  database.md
  rules.md
  testing.md
  troubleshooting.md
  help.md
  faq.md
```

Nem todos os arquivos sao obrigatorios. A task deve criar apenas o que fizer sentido para a funcionalidade entregue.

## Checklist Por Funcionalidade

- objetivo;
- publico-alvo;
- status no produto;
- escopo implementado;
- fora do escopo;
- regras de negocio;
- regras multi-tenant e multi-filial;
- permissoes;
- eventos e auditoria;
- telas e rotas;
- API e payloads;
- testes;
- comandos de validacao;
- limites conhecidos;
- ajuda do usuario;
- FAQ;
- impactos comerciais ou operacionais;
- referencias oficiais consultadas.

## Help Center

Quando a funcionalidade tiver uso operacional, criar conteudo de ajuda com:

- titulo claro;
- pre-requisitos;
- passo a passo;
- resultado esperado;
- erros comuns;
- links relacionados.

## Academy

Academy deve explicar o conceito reutilizavel, nao apenas repetir a tela.

## Material Comercial

Material comercial futuro deve transformar capacidades em beneficios sem prometer funcionalidades ainda nao implementadas.
